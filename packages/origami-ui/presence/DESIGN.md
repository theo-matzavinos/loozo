# Presence design map

Ownership and read timing. Usage is in the [README](README.md); the contract is SPEC section 7.

## Ownership

| Fact                        | Owner                                                                                                                                                                                                                                                                                                                        | Readers                                                                                 |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Desired presence            | the effective `OrigamiPresenceOptions` on the same element                                                                                                                                                                                                                                                                   | the current transition                                                                  |
| Current transition          | `PresenceContext`, a `linkedSignal` over desired presence; each new transition is a new object, kept when it settles                                                                                                                                                                                                         | `phase`, discovery, completion, the floating piece's position snapshots and reveal gate |
| Settled                     | `PresenceContext`, a `linkedSignal`: always true on the server (SSR settles); on the client reset by each new transition and set by completion                                                                                                                                                                               | `phase`, discovery                                                                      |
| Phase                       | derived from the transition's direction and whether it has settled                                                                                                                                                                                                                                                           | the host markers, State                                                                 |
| Pending discovery and waits | the transition object they captured; work belongs to the current transition only while it's the same object and the adapter's lifetime unchanged                                                                                                                                                                             | `#isCurrent`, which also drops work after destruction                                   |
| Initial phase on the client | the server's `data-present` attribute on the reused host, read at construction                                                                                                                                                                                                                                               | the first settled computation                                                           |
| Entering permit and reveal  | `ɵOrigamiPresencePresentation`, the presentation adapter of floating Content (Popover), on the same element, keyed by transition object; its native lifetime is the adapter's own generation, advanced by its `reset()` when `ɵOrigamiFloating` releases a native activation (see [popover/DESIGN.md](../popover/DESIGN.md)) | `entering`, discovery                                                                   |
| Animations                  | the host's CSS                                                                                                                                                                                                                                                                                                               | discovery (`getAnimations()`)                                                           |

## Read timing

| Read                                   | Reader                                                          | Phase                   | Platform | If the owner isn't initialized                                                                                                                                                                                                        |
| -------------------------------------- | --------------------------------------------------------------- | ----------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data-present` attribute               | constructor field                                               | construction            | both     | On hydration the reused server element carries it; on a client-only render it's absent. The markers are reserved, not consumer-authored.                                                                                              |
| Own Options `present()`                | the current transition                                          | render                  | both     | Safe: own element, inputs set before its host bindings.                                                                                                                                                                               |
| The floating piece's entering permit   | `entering`, for `[attr.data-entering]`                          | render                  | browser  | No permit yet: no `data-entering`, and Presence stays `opening`. The floating piece permits it after its coordinates resolve and schedules the render that applies it (SPEC-POPOVER.md).                                              |
| The floating piece's reveal commit     | discovery                                                       | after render            | browser  | Not committed: discovery waits for a later render's READ.                                                                                                                                                                             |
| The adapter's `visual()`               | discovery                                                       | after render            | browser  | No revealed native host while `closing` (closed before reveal, suppressed or hidden): completion settles `closed` in the same READ, without waiting for `data-leaving` or animations.                                                 |
| The adapter's `captureLifetime()`      | discovery WRITE, `#isCurrent`                                   | after render, microtask | browser  | `0` without an adapter. Its `reset()`, which the floating piece calls when it releases a native activation, advances it while the transition object stays the same, so a released native activation's waits stop counting as current. |
| Current transition                     | the adapter's `captureTransition`, called by the floating piece | after render, event     | browser  | Safe: a signal read. After destruction it returns an object no pending work holds.                                                                                                                                                    |
| `getAnimations()`, `hasAttribute(...)` | `afterEveryRender` read                                         | after render            | browser  | Runs after every owner's WRITE in the same render.                                                                                                                                                                                    |

## Refresh dependencies

- Settling only writes the settled signal, from the READ or an animation-completion microtask. Applying it, by removing `data-entering` or `data-leaving`, setting `data-present` and releasing children gated by `state.open()`, takes the render Angular schedules for that signal write. This holds for direct and composed Presence.
- A floating-composed entrance (Popover Content) also depends on the render the floating piece schedules after permitting entry: it applies `data-entering`, and the following READ discovers the entrance.
