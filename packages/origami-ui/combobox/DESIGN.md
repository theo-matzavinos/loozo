## Refresh dependencies

- The session cleanup runs from an effect that reads the requested `open` and the pending session, and whenever the requested state is closed while a session is pending, clears the flag, clears the active option with its pending scroll and writes the committed text to `query`. Every opening and close the Combobox makes itself (an edit, an opening key, a key in the open list, the Trigger's click, a close without a choice) sets the pending session in its own event, so the cleanup doesn't depend on the effect having seen the list open: an open the consumer cancels from `openChange` or a microtask before any effect runs still reverts and clears the highlight, and a close from an already closed list (focus moving to another element with an adopted draft) reverts. A choice runs the cleanup at once after its close, writing nothing as the committed text already is the query. The effect always reads the pending session, so clearing it while the list stays open reruns it and an open request it sees starts a session again. An open from elsewhere (an `open` write) starts one only once the effect sees it, so an outside `open` true and false written before the effect runs, with no user action between them, leaves nothing pending: the query then already is the committed text unless it holds an adopted draft, which stays (SPEC section 31's one exception).
- The active option is also cleared by an effect when participation changes from true to false while the request stays open, as when an enclosing layer closes; every edit and every opening key set or clear it themselves.
- Disabling closes an open Combobox from an effect that watches the root's disabled state change from enabled to disabled.
- The input's `value` binding writes only a query that differs from its last write, so it misses an edit the consumer undoes, from `queryChange` or later before the next render, by writing back the text the input showed before. The input therefore writes the query into its element itself when the element's text differs, from an `afterRenderEffect` created in its `ngOnInit` that reads the root's query signal itself (`ComboboxContext.query` isn't memoized, so a write restoring the text it last read still reruns it) and the composition flag: after every render in which either changed, so after a composition's end too, where an engine's last `input` event after `compositionend` writes its own text first. Outside a composition only.
- The committed text is a `linkedSignal` over the query, read before and after each of the Context's own query writes, so an outside write between two of them is taken and the Context's write isn't.
