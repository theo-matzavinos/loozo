# Utilities design map

Ownership and read timing for `injectUniqueId`, `injectUniqueValue`, `injectDeferred` and the package-private `ɵOrigamiDescribedBy`, then for the package-private dismissal layer and presentation contract that Popover, Tooltip and Dialog share. Usage is in the [README](README.md); the contracts are SPEC sections 4 and 5, and for the layer SPEC sections 10, 18 and 22 and [SPEC-POPOVER.md](../SPEC-POPOVER.md). The layer's machine runs in document events and tasks, never in a part's host bindings.

## Dismissal layer (`ɵOrigamiLayer`, `ɵOrigamiLayers`)

`ɵOrigamiLayer` is one per owner (Popover root, Tooltip root, Dialog Content's modal session), constructed by the owner after its presentation and destroyed first in its teardown. `ɵOrigamiLayers` is the application `@Service` with the document listeners: Escape, the outside-pointer gesture, the order counter, veto preflight and descendant-first dismissal. It also keeps the modal scopes: every registered modal owner (Dialog Content's session), open or not. A layer's modal scope (`scope()`) is the innermost one whose `<dialog>` contains all of the layer's registered parts in the flat tree, through shadow roots and slot assignment, where a light-DOM child no slot takes and slot fallback content an assigned node replaced are outside. So a Popover, Tooltip or Dialog declared inside Dialog Content, projected into it through `<ng-content>`, in a shadow root inside it, or slotted into a shadow root's `<dialog>` belongs to that Dialog alike. Scope is computed from the DOM at each read, in synchronization and events, never during render; a DOM move that isn't a signal change, such as a changed `slot` attribute, counts from the next read. A Popover without a parent Popover joins its scope's branch; a Tooltip and a Dialog don't. The topmost search considers, while a modal owner participates, only the newest modal owner and the layers whose parts are inside its `<dialog>`: the rest of the page is inert. `dismissTopmost` applies Escape's rule, the same topmost search the keydown handler uses, to a close request Escape doesn't dispatch: a native `cancel` on the topmost Dialog. On an older Dialog, the `cancel` dismisses its own branch through `dismiss`. A branch whose owner's intent is closed, a Dialog running its exit, consumes the request without writing anything, so its suppressed members keep their requested state.

## Presentation contract (`ɵOrigamiPresentation`, `ɵOrigamiPresentationChild`, `ɵOrigamiPresentationScope`)

`ɵOrigamiPresentation` is what a dismissal layer and a nested presentation read from a presentation; `ɵOrigamiPresentationChild` is what a presentation reads from the nested presentations it keeps. `ɵOrigamiFloating` (mapped in [popover/DESIGN.md](../popover/DESIGN.md)) implements both; Dialog Content's modal session (mapped in [dialog/DESIGN.md](../dialog/DESIGN.md)) implements `ɵOrigamiPresentation` and keeps participating through its exit, while it still blocks the page. The contract owns no state: each member reads the implementing presentation's own.

### Ownership

| Fact                                                                                         | Owner                                                                                                                                                                          | Readers                                                                                                                               |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| Participation, order, activation, epoch, readiness                                           | the implementing presentation                                                                                                                                                  | its owner's layer; a nested presentation (readiness, epoch)                                                                           |

| Presentation children                                                                        | the parent presentation, an immutable `Set` replaced on `addChild` and `removeChild`, called when a child's synchronization resolves a different parent and at its destruction | the parent's close and suppression (`desired`, `suppress`) and reveal commit (`parentRevealed`)                                       |
| The enclosing Popover's presentation                                                         | `ɵOrigamiPresentationScope`, provided by Popover Content as its owner's `ɵOrigamiFloating`                                                                                     | a Tooltip root inside that Content, at construction, as the parent it resolves first                                                  |
| The modal scope's presentation                                                               | the scope layer's `presentation`, a Dialog's modal session                                                                                                                     | a Popover root without a parent `PopoverContext`, and a Tooltip root outside Popover Content, as the presentation parent they resolve |
