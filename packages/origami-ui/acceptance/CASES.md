# Public acceptance cases

**Case definitions for the product contract.** [`tests/acceptance`](../tests/acceptance/README.md) executes them against the genuine built library; the supplied consumers seed common paths and the suite adds the case-specific variants. References such as R/V/H mean sections 7/10/12 of the product contract, not private implementation APIs.

For every case record fixture/source identity, engine/build/hydration mode, inputs/action, actual observations and pass/fail. Observe phase/retention/native participation separately. Poll observable completion with a bounded test timeout; do not implement duration-guessing library timers or treat a sleep as evidence. Use genuine dependency behavior and real trusted browser actions when the claim requires them.

Synchronous native callback reentry claims require a factory-backed root variant writing the actual effective writable `open`, with public State observed before the callback returns. Parent-binding updates alone cannot certify that interleaving. Correlate focus events with fresh native activation versus retained-exit reuse rather than treating a focus counter as an autofocus-activation count.

## Done boundary

A release requires that all required case variants have independently reviewed assertions and genuine executed evidence; full public TSDoc survives packaging; B1 is recorded skipped without a qualification claim; missing/unsupported optional enhancement evidence is clearly distinguished. A fake environment, private test API or broader platform is not evidence.
