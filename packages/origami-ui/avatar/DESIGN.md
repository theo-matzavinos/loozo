## Refresh dependencies

- A source change: `source` changes, so the observation resets and the render that writes the new `src` reads `loading` (or `idle`). The after-render reconcile tracks `source`, so it runs after that render, in the same tick, and may settle the status before any paint.
- An observation write (reconcile from the effect or a native event) schedules the next pass, which updates `data-status` and the `hidden`/`aria-hidden` attributes.
- The observation and the effect see a source change only when a read of `source`, a `computed`, finds a different value. Writes that return to the same effective value before anything reads it (A → B → A in one turn, or a bound input whose intermediate value never reaches the Image) may cause no transition: the observation isn't reset and the effect doesn't rerun.
- Hydration: no observation exists on the server or in the first client pass, so nothing differs from the server HTML until the Image's first browser after-render. The first client binding pass writes the unchanged `src` attribute again, which the browser treats as a new image update (README, Server rendering and hydration): every engine fires `load` or `error` again after the Image's listeners exist, and Firefox resets `complete` until then, so in Firefox the native listener, not the first reconcile, settles an image complete before hydration. Chromium and Firefox also request an image that had failed once more, so its status stays `loading` until that retry's `error` (or `load`); Firefox requests an image still loading a second time. Either way the status is read from the element.
