# Date picker design map

Ownership and read timing. Usage is in the [README](README.md); the contract is SPEC section 27. The composed Popover's map is in [popover/DESIGN.md](../popover/DESIGN.md), the bound Calendar's in [calendar/DESIGN.md](../calendar/DESIGN.md) and the composed date field's in [date-field/DESIGN.md](../date-field/DESIGN.md).

```text
[formField] ─binds─► ogDatePicker (value/open models, touch, focus, clear)
                       ├─ composes ogPopover (open = root.open, disabled = root.disabled)
                       ├─ composes ogDateField (value, locale, disabled, readonly = root's)
                       └─ ogDatePickerContent provides ɵOrigamiCalendarPicker
                                 ▲ value/disabled/readonly, chosen(), register()
                          ogCalendar inside Content (all other configuration its own)
```

## Read timing

| Read                                                                               | Reader                                                    | Phase                | Platform                                       | If the owner isn't initialized                                                                                                                         |
| ---------------------------------------------------------------------------------- | --------------------------------------------------------- | -------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Root Options                                                                       | every part's host bindings, State, the bridge's fields    | render               | both                                           | Safe: an ancestor, read through `injectDeferred` after construction.                                                                                   |
| The bridge (`ɵOrigamiCalendarPicker`)                                              | the Calendar root's Options factory, State and `ngOnInit` | construction, render | both                                           | Content is the Calendar's ancestor and provides it; its fields read the root's Options lazily.                                                         |
| Registered Trigger `labelledBy`, template `aria-label`, ID                         | Content's `aria-labelledby` and `aria-label`              | render               | both                                           | Absent until the Trigger registers; a Trigger authored after Content registers later in the same change detection, which refreshes Content's bindings. |
| Root form state                                                                    | the Trigger's membership                                  | render               | both                                           | Read only once the Trigger has registered, after Angular set `[formField]` on the root.                                                                |
| Effective `open`                                                                   | the reset effect                                          | effect               | both                                           | A view effect on the root's view; a Calendar not registered by then is reset at its registration (`ngOnInit`), before its first render.                |
| Effective disabled                                                                 | the close-on-disable effect                               | effect               | both                                           | A view effect on the root's view; the first run only records the state.                                                                                |
| Participation, registered Calendar                                                 | the focus effect                                          | effect               | browser (participation is false on the server) | Waits: a gated Calendar mounts later, and participation follows the native show.                                                                       |
| Registered Calendar `focusPending()`                                               | `focusOut`                                                | event                | browser                                        | No Calendar: no exception, a `focusout` to nothing touches.                                                                                            |
| Root element containment, `relatedTarget`, `[inert]` ancestors, effective disabled | `focusOut`                                                | event                | browser                                        | Live DOM.                                                                                                                                              |
| Registered Trigger element                                                         | the root's `focus()`                                      | event                | browser                                        | Nothing before the Trigger registers.                                                                                                                  |

## Refresh dependencies

- Content's name reads the Trigger's registration: a Trigger authored after Content registers in its `ngOnInit`, and the signal it writes refreshes Content's bindings in the same change detection, also on the server.
- The open session's two effects run in the root's view; the focus request is served when participation changes after the native show (Popover's after-render work), which schedules another change detection.
- A completed choice writes `open` false from the cell's event; Popover restores focus in the `earlyRead` after that render, so the Trigger's text in its own view, an embedded view or a child component is rendered first. Content turns inert in that render's host bindings, before the restore: Chromium can drop focus to nothing in between, which `focusOut` doesn't count as leaving (the target is inside an inert element).
