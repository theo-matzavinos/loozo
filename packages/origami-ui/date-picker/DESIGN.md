# Date picker design map

Ownership and read timing. Usage is in the [README](README.md); the contract is SPEC section 27. The composed Popover's map is in [popover/DESIGN.md](../popover/DESIGN.md), the bound Calendar's in [calendar/DESIGN.md](../calendar/DESIGN.md) and the composed date field's in [date-field/DESIGN.md](../date-field/DESIGN.md).

```text
[formField] ─binds─► ogDatePicker (value/open models, touch, focus, clear)
                     │ or ogDatePickerMultiple / ogDatePickerRange / ogMonthPicker
                     │    (value/open models, touch, focus)
                       ├─ composes ogPopover (open = root.open, disabled = root.disabled)
                       ├─ ogDatePicker only: composes ogDateField (value, locale, disabled,
                       │    readonly = root's; its Input and segments hold the Trigger in the
                       │    field shape)
                       └─ ogDatePickerContent provides ɵOrigamiCalendarPicker (the root's mode)
                                 ▲ value/disabled/readonly, chosen(), register()
                          the Calendar root of that mode inside Content: ogCalendar,
                          ogCalendarMultiple, ogCalendarRange or ogMonthCalendar
                          (all other configuration its own)
```

Every root provides the same private `DatePickerContext` through `DatePickerRootOptions` (its mode and its effective value, open, disabled and readonly), so the Trigger, Content and everything below hold for all four; only `ogDatePicker` has a date field, so only it has the field shape.

## Refresh dependencies

- Content's name reads the Trigger's registration: a Trigger authored after Content registers in its `ngOnInit`, and the signal it writes refreshes Content's bindings in the same change detection, also on the server.
- The open session's two effects run in the root's view; the focus request is served when participation changes after the native show (Popover's after-render work), which schedules another change detection.
- A completed choice writes `open` false from the cell's event; Popover restores focus in the `earlyRead` after that render, so the Trigger's text in its own view, an embedded view or a child component is rendered first. Content turns inert in that render's host bindings, before the restore: Chromium can drop focus to nothing in between, which `focusOut` doesn't count as leaving (the target is inside an inert element).
