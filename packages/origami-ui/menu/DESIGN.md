## Refresh dependencies

- Content's `aria-labelledby` and a group's `aria-labelledby` read registrations that a Trigger or label makes in its own `ngOnInit`, possibly after the reader's host bindings ran: the registration changes a signal the binding read, so Angular refreshes that view again in the same change detection, on the server too.
- The pending entry is bound to the open decision it was made under: `intent` is recomputed for every write that changes the effective `open`, so a close and a reopen written before effects run still invalidate it, with no effect involved. An opening binds its request only after its own `open` write returns, to the decision in force then: a close and reopen its `openChange` listeners write during the write receive it, and any write after it invalidates it. Every new request writes a new entry object, so a reopen never fulfils an older one. The entry effect reads the roving focus's membership through `focusEdge`, so it runs again when items register after the reveal.
- The typeahead buffer and the search's held Space are reset by an effect when the requested state closes; the buffer also expires 500 ms after its last character.
